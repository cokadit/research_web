# Lead research and outreach system

Single-user, self-hosted system for Agung Aditya (freelance web/UI-UX designer, Bali). It finds independent businesses with weak websites, scores them, and queues them for human review. The full spec is `prompt.md`. Read it before any phase work.

## Current phase

**Phase 1 (research engine) is built and waiting for approval.** Do not start Phase 2 until the user says so.

- Verified in mock mode only. No Gemini, PageSpeed or Places key has been used yet.
- The acceptance run with 20 real candidates is still open. It needs `LLM_MODE=live` plus Gemini and PageSpeed keys.
- Plan and decisions: `docs/phase-1-plan.md`.

## Working rules (from prompt.md section 0)

- Build in phases, stop after each one with a short report.
- Plan before coding. Ask before adding a dependency that is not already in `package.json`.
- Never write model IDs, SDK method names, field masks or prices from memory. Check official docs, put model IDs in `.env`, mark anything unverified with `// TODO(verify): …`.
- No real email before Phase 3 is approved. `SEND_ENABLED=false`.
- Secrets only in `.env`. Keep `.env.example` current.
- Validate every LLM output and external API response with zod.
- Never fetch Instagram, marketplaces (Shopee, Tokopedia, Etsy), Airbnb or Booking.com. `isNoCrawlHost()` enforces this.
- Crawling: robots.txt respected, 1 concurrent request per domain, 2 s gap, 20 s timeout, clear user agent. `PolitenessGate` enforces this.

## Machines

- Code is written on a Mac that has no Docker and no Postgres.
- The system runs on a spare **Windows** PC (native, no WSL workflow), always on, reached over Tailscale.
- So: no bash in npm scripts, build paths with `node:path`, and set `CLAUDE_BIN` to the full path of `claude.exe` on Windows.

## Conventions

- **Imports:** relative inside `src/`, `worker/` and `scripts/`. The `@/` alias (repo root) only inside `app/` and `components/`.
- **Pure logic stays free of database imports**, so unit tests run without Postgres. Example: `pagespeed-parse.ts` is pure, `pagespeed.ts` does the call and logging.
- **Queue names use dots:** `discover.daily`, `enrich.company`, `score.company`, `queue.build`. pg-boss rejects colons.
- **Model IDs** come from `.env` through `src/lib/llm/routing.ts`. None in code.
- **Every LLM call** goes through `validatedCall()`: zod validation, one retry with the error appended, one `llm_calls` row per attempt.
- **Server Actions** call `requireSession()` first. The proxy alone is not enough.
- **Label helpers** used by server components live in `components/leads/labels.ts`, not in a `'use client'` file.
- **Schema changes:** edit `schema.ts`, run `npm run db:generate`, commit the migration.
- **Spelling:** British English in code and UI (`normalise`, `unauthorised`).

## Pipeline in short

1. Discovery inserts companies with `status=new` after normalising and de-duplicating the domain.
2. Enrichment crawls, measures and classifies, writes a `signals` row, sets `status=enriched`.
3. Scoring computes N/P/C/F and priority for every lead, then `decideTier()` sets `scored`, `not_qualified` or `auto_excluded` and stores every failing code in `fail_reasons`.
4. Scoring only moves leads that are still in the pipeline. A lead the user already decided on keeps its status.

## Fail codes added beyond the spec

`robots_blocked`, `wrong_segment`, `enrich_incomplete` (all tier 2). `major_brand_uncertain` is the code for "major_brand with medium or low confidence".
